# SEO and Performance

Inspect the actual framework, routes, metadata, assets, dependencies, and project conventions before recommending or changing a site.

For a review, prioritize concrete issues supported by the code or measurements. Check semantic structure, headings, document language, titles/descriptions, canonical and social metadata, robots/sitemap conventions, accessible names and focus, responsive rules, image/font loading, and avoidable client JavaScript where relevant. Use browser, accessibility, or performance tools only if they are available; distinguish source review from a measured audit.

When asked to implement, make scoped local changes that preserve the brand and existing behavior. Run the existing relevant checks and report only what actually ran. Do not add dependencies without a clear need, invent Lighthouse/Core Web Vitals results, or deploy, publish, push, or modify production.
